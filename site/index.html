A software team for AI coding agents

The team weaves your app.

Knit gives your coding agent a whole team's discipline: product thinking, a lean plan, design polish, tests, review, docs and a live deploy, at the cost of one normal session. You approve every step.

01 · Plan

One round of questions. One page.

Clickable questions: must-haves, stack, where it goes live, solo or team. Then one page: stories with acceptance checks, the look, the build, the tasks.

The Lean checklist cuts what doesn't need to exist: the platform first, then one line, only then new code.

You approve the plan.
02 · Build

Slice by slice.

Your session puts on each role's hat with short checklists. In chunks by default: a foundation, then thin end-to-end slices of 1 to 4 stories, so you see working software after the first chunk.

  • Smallest working slice first; reuse before writing.
  • Input validated at the boundary; secrets only in environment variables.
  • Run and clicked through before a slice counts.
03 · Tests

Tests where they pay.

Unit tests for logic with branches, maths, parsing, money or security. One or two end-to-end checks for the core flow. Commands run once and exit, so nothing runs unwatched.

  • Every build ends with an 11-check quality card.
  • Tests, build, the core flow in a browser, light and dark, phone width, states, keyboard, contrast, security, lean, README.
04 · Review

One pass, every angle.

One Reviewer pass over the diff: bugs, security, lean (dead code, duplicates, hand-written built-ins), accessibility and design polish. What it finds is fixed now, not filed for later.

05 · Ship

Live, with your OK.

A README with the Built with Knit badge, a live deploy (Vercel by default) and a smoke test of the live URL. You sign in to your own accounts; Knit never handles credentials.

You approve going live.

    Bring an idea.

    Clone Knit, open your coding agent in the folder and describe what you want. The team builds in a sibling folder and puts it live when you approve.

    FAQ

    Questions, answered.

    Does Knit cost more than a normal session?

    Not in solo mode, the default. On the same calculator a plain session used 117,960 tokens and Knit used 124,120 (+5%). Team mode used 268,021, because every agent re-reads the project, and Knit tells you that before you pick it.

    What's the difference between solo and team mode?

    In solo mode one session wears every role's hat with short checklists. In team mode the specialist agents work in parallel for speed. You choose at intake.

    Does anything go live without me?

    No. You approve the plan, every chunk when you build in chunks, and going live. Deploys go to Vercel by default once you say go, and you sign in to your own accounts.

    Which coding tools does it work in?

    Claude Code, Codex, Cursor, OpenCode and Antigravity. Knit is written once and scripts/install.mjs installs it in each tool's own format.

    In chunks or the whole project at once?

    Chunks are the default: chunk 0 is the foundation, then thin end-to-end slices of 1 to 4 stories, so problems are caught early. Whole-project mode suits small, well-defined apps.

    Where does my project go, and what's logged?

    The team builds in a sibling folder, ../<project-name>. Every step is appended to .knit/events.jsonl, and node scripts/knit-report.mjs ../my-project turns it into a run report, a token report and a chart.

    What is the Knit Board?

    The live view of a run. /knit-build starts it and opens it in your browser; --replay replays a finished run. It has no dependencies and no build step, and it only listens on 127.0.0.1.

    Can the docs live in Notion?

    Yes, if a Notion connector is available Knit asks at intake. It keeps a page per project with the brief, plan, quality card and reports, updated at every gate. The files in .knit/ stay the source of truth.
